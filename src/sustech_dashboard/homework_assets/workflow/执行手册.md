根目录：`D:\Artifacts\Homework\2026-Fall`。业务规则见 [README.md](README.md)，新窗口入口见 [../工作流入口.md](../工作流入口.md)。下面的 `<directory>` 是 `homework_sets.json` 的精确 `directory` 值，不是课程显示名称。

## 1. 环境与只读恢复

调用 ChatGPT 桌面端中的 Codex 的 `load_workspace_dependencies` 发现当前 Python；不要猜安装版本。当前工作包使用 `pypdf`、`pypdfium2`、Pillow，精确计算还可使用 SymPy。SymPy 的本机已存副本位于 `D:\Caches\homework-python-libs`，需要时仅为本次进程添加到 `PYTHONPATH`。

PowerShell 变量示例，先替换为本次发现的路径与已确定的任务：

```powershell
$py = 'C:\Users\fy\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe'
$base = 'D:\Artifacts\Homework\2026-Fall'
$w = Join-Path $base 'workflow'
$d = '<directory>'
Set-Location -LiteralPath $base
& $py "$w\check_handoff.py"
```

长命令采用本机 `windows-terminal-timeout` skill 的进度规则。终端无输出时先查运行态；若当前 PowerShell 启动确实失败，可用工具提供的 Python 直接执行同一脚本，保留具体失败证据，不改用 GUI。

在新任务写入前核对：`homework_sets.json` 对应条目、`output-layout.json`、`output-verification.json`、`output-derivatives.json`（如存在）、目标作业 `交付清单.json`。当前默认原件目录为 `D:\Downloads`；实际默认下载目录或用户指定路径优先。

## 2. 建立制作目录与冻结原题

从 [templates/homework.json](templates/homework.json)、[templates/sources.json](templates/sources.json)、[templates/题目.md](templates/题目.md) 开始。删除模板占位并填入真实数据后，再将 homework 条目合并到根目录 `homework_sets.json`，按 `directory` 唯一；同一课程的标签和三册文件名不得冲突。新任务必须保留本地 `homework.json`，并与总清单对应项完全相同；中文附件的渲染器从本地文件读取语言标志。

新课程须在 `output-layout.json` 显式登记 `homework_copies`，不能根据课程名自动猜测。清单整体型课程的分节／周／章组织继承用户明确要求；需要合订时另读已有衍生文件登记，不自动新增合订本。

制作目录结构：

```text
<directory>/
  homework.json
  题目.md
  题目-英文.md                  # 原中文附件才需要
  答案册-英文.md
  答案册.md
  figures/                      # 有图时使用
  review/
    sources.json
    source-pages/               # 原页图和必要局部图
    source-review/              # 图像复核原始响应
    solutions-production/      # 英文解答原始响应
    accepted-solutions.json
    calculation-review.json
    translation/
      <run>/<id>.json
      selection.json           # 本作业的选择表，优先于旧全局表
      accepted.json
    pdf-pages/                 # verify_booklets.py 渲染
    codex-review.json           # AI 实际完成审核后填写
    final-verification.json
  build/                        # 生成的 TeX、PDF、日志
  交付清单.json                  # 交付脚本生成
```

`题目.md` 用精确独占一行的 `### Problem 2.2.2` 分题；纯编号附件用 `### Problem 1`。题号只支持数字与点；不得以页码、题干中的交叉引用代替标题。每题包含完整题干、分问和所需图，行内 `$...$`、行间 `$$...$$`，分式写成 `\frac{...}{...}`。复杂表格使用 LaTeX `array`，当前渲染器不解析 Markdown pipe table。

先把作业截图／清单复制到本作业的 `inputs/` 并登记哈希，不只保存临时剪贴板路径；教材可继续引用原文件，记录其 SHA-256。对照原页确认版次、节号、题型和相邻题后再录题。跨页题收齐续页；图题同时核读整页和局部刻度。保留 PDF 页序号（从 1 开始）、印刷页码和原文件 SHA-256。

## 3. 图像复核、英文解答与独立验算

`api_tasks.py` 是批处理适配器，不会替代 AI 判断。使用前读取本机 `ai-production-supervisor` skill，发现当前模型配置；它目前还引用 `Physics-Ch02-Ch03/review/produce_solutions.py` 的配置函数和该 skill 的 `run_ai_batch.py`，这两处是工作包的现有依赖。

JSONL 的每行形如：

```json
{"id":"2.2.2","input":"### Problem 2.2.2\n\n完整候选题面","requires_visual":true,"images":[{"path":"D:/.../原页.png","detail":"original"}]}
```

图像复核使用 [vision-review.md](vision-review.md)，英文生产使用学科适配的 Prompt；[solution-generation.md](solution-generation.md) 当前专用于线性代数，不能直接当物理或微积分通用 Prompt。参考 `LinearAlgebra-HW4/setup_jobs.py` 的任务结构，但不要执行它来准备新 homework。

```powershell
& $py "$w\api_tasks.py" '<本作业源图复核jobs.jsonl>' "$w\vision-review.md" '<本作业复核输出目录>'
& $py "$w\api_tasks.py" '<本作业解答jobs.jsonl>' '<对应学科的Prompt.md>' '<本作业候选输出目录>'
```

执行图像能力 Canary；不可读则标 unresolved，不能用纯文本转述替代实际图像输入。复核失败由 Codex 回原件裁决。数学答案独立验算每个中间式、参数情况、单位和方向；证明题另查量词、边界和前提，数值试验不能代替证明。

接受后组装 `答案册-英文.md`：每题完整英文题面，随后 `#### Solution` 与英文解答；题号和顺序严格一致。英文教材题干与 `题目.md` 逐段相同。原中文附件先生成 `题目-英文.md` 并审查数学与语义对应，设置 `answer_stems_translated=true`，最终发布时由组装器恢复原中文题面。

`accepted-solutions.json` 每题保存 `id/candidate/sha256/source_review/source_sha256`，路径指向未改写的候选响应。`calculation-review.json` 保存实际计算、证明审核和状态，分别使用 [接受记录模板](templates/accepted-solutions.json) 和 [验算模板](templates/calculation-review.json)。英文组装目前由当前 AI 根据新题和接受记录完成，没有自动求解或自动选择候选的公共命令；旧样例的 `assemble_english.py` 不可直接用于新作业。

独立图像模型失败而 Codex 能根据原图裁决时，保留失败原始响应，另存 [source-adjudication.json](templates/source-adjudication.json) 格式的裁决记录。实际核读后填写原图、原文、依据和失败记录路径及哈希，输出中的 status 才能改为 pass；`accepted-solutions.json` 的 `source_review` 指向这份新记录。它采用签收器可读取的证据结构，不能改写旧模型响应，也不能宣称外包识图通过。

## 4. 专用翻译与选择

固定调用 `D:\Artifacts\TranslationPrompts\translate.py` 的规则。密钥按该入口与 skill 的本机发现链读取，不写入本包、不打印、不向用户重复索取已有配置。模型与思考模式按实际质量选择；当前脚本默认模型继承专用翻译入口的 `MODEL`。

先做无 API 的范围核验，再执行翻译：

```powershell
& $py "$w\translate_protected.py" --homework $d --list-only
$env:HOMEWORK_TRANSLATION_THINKING = 'enabled'
$env:HOMEWORK_TRANSLATION_RUN_SUFFIX = '-r01'
& $py "$w\translate_protected.py" --homework $d
# 重跑某题时，显式添加该作业内的题号，并使用新的 run suffix。
```

不再支持只给题号而不指定 homework 的命令。每题提供整份 homework 的英文上下文；公式、标签、图片引用、专业词和段落标记受到保护。`structural_errors=[]` 只表示结构合格，仍须对照英文检查译文语义。

AI 审核后填写本作业 `review/translation/selection.json`，使用 [templates/translation-selection.json](templates/translation-selection.json)；键须恰好覆盖本作业题号。新作业不要继续往旧全局 `workflow/translation-selection.json` 增加裸题号。旧作业仍可读取旧表。

```powershell
& $py "$w\assemble_chinese.py" $d
```

该步骤保存 `答案册.md` 与 `review/translation/accepted.json`，核对源文哈希及段落、公式、题号、图片引用等结构。不得直接改写失败译文；修正通用提示或保护规则后，从英文源文重跑。

## 5. 排版与 PDF 检查

```powershell
& $py "$w\render_booklets.py" $d questions writing solutions
```

通过当前本地 LaTeX/Tectonic 编译器生成 `<directory>/build/questions.pdf`、`writing.pdf`、`solutions.pdf` 并保留日志。单个独立 LaTeX 文档使用内置编辑器与编译诊断；本工作包的批量导出沿用本地编译流程。不要把内置编译诊断成功等同于磁盘 PDF 已导出。

`compile_selected.py` 的现有快捷方式要求：制作目录直接位于工作包根目录、存在匹配的 `homework.json`、且 `CODEX_TECTONIC_PATH` 指向实存可执行文件。满足时：

```powershell
& $py "$w\compile_selected.py" $d questions writing solutions
```

嵌套目录（如 `Calculus-I/Section-2.1`）使用上面的 `render_booklets.py`，再按已发现编译器的实际 CLI 分别编译三个 TeX。发现编译器按当前 LaTeX 工具或 `latex-doctor` 能力检查；不复制旧 WindowsApps 版本路径，也不为本次接手自动安装大型 TeX 环境。

```powershell
& $py "$w\verify_booklets.py" $d
```

该脚本检查题号、顺序、正文次序、页数、A4、图、编译日志并逐页渲染，视觉状态仍为 PENDING。Codex 必须看所有页的联系表和密集页全尺寸图，确认公式可读、无裁切重叠、分页合理，尤其检查作答续页只有横线。

## 6. 记录实际 AI 审核，再交付

从 [templates/codex-review.json](templates/codex-review.json) 填写 `review/codex-review.json`。记录实际日期、审核题号、四阶段结论；已解决问题写入各阶段 notes，`findings` 只列未解决问题，通过时必须为空。绑定当前三份 Markdown、证据记录、三份 PDF 和**每一张当前 PDF 页图**的 SHA-256。`rendered_page_hashes` 使用 `questions-01.png`、`writing-01.png`、`solutions-01.png` 等相对文件名；旧多余页图不能算入覆盖范围。

审核是 AI 的工作，不需要用户批准；脚本只能校验这些记录与当前文件相符。缺少记录、PENDING、未消除问题、漏页或哈希变化均不得签收。文件重建后重新检查受影响内容，不通过复制上次结论恢复 PASS。

```powershell
& $py "$w\finalize_booklets.py" $d
& $py "$w\deliver_booklets.py" $d
& $py "$w\verify_output_layout.py"
```

`finalize_booklets.py` 适用于本手册的每作业证据结构。历史批次可能把来源及验算放在课程公共目录，继续读取它们的历史报告；新任务采用本手册结构，不为统一结构重写旧交付。`deliver_booklets.py` 生成三册、完整 ZIP、交付清单并调用导出。最终目录审核读取真实文件及哈希，也校验登记过的合订本。

核验、签收、交付应在输入冻结的一轮中连续执行；签收后任何证据变化均回到审核阶段。不能仅因为历史 `交付清单.json` 写着 DELIVERED 就判断本轮成功，还必须核对本轮命令、导出回执和目标文件哈希。现有导出器会核对旧输出目录；若旧作答文件已被用户填写，它可能拒绝新增导出，不能覆盖用户文件或篡改旧回执来放行。先只读检查旧输出，发现差异时报告具体文件，再选择用户已授权的独立输出位置或精确处理该冲突。

完整 ZIP、制作 Markdown 和审核记录留在制作层。三册进入课程三类目录。当前 `deliver_booklets.py` 的自动导出固定使用默认 output；自定义 output 尚未贯通这条自动链。用户指定其他位置时，不要先运行它向默认位置写入；由当前 AI 根据已核验 PDF 做有界复制、按指定位置保存独立交付回执并核对哈希。`export_output.py --output ...` CLI 会导出全部已登记作业且复用全局回执，不用于单份自定义交付。全局 `verify_output_layout.py` 用于当前登记的完整默认布局，不把它冒充自定义子集验收。

## 7. 续跑和脚本边界

| 发现的状态 | 下一步 |
| --- | --- |
| 原件／题号尚未核清 | 留在源文阶段，不开始解答 |
| 原页复核 unresolved | 补局部图、相邻页，回原件核读 |
| 英文答案不正确 | 保留失败候选，修改通用生成／验证方法，重新生成 |
| 翻译结构或语义失败 | 新 run suffix 重跑，保留英文源文与失败响应 |
| PDF 已编译但视觉 PENDING | 看渲染图、处理版面，再记录实际审核 |
| 输出 PDF 与交付哈希不同 | 识别用户手写或其他变更，禁止自动覆盖 |
| 当前任务已经交付且哈希一致 | 直接提供既有结果，不重复 API 或编译 |

`record_review_completion.py`、各旧批次 `finalize_reviews.py`、`native_translation_retry.py`、`repair_translation_paragraphs.py` 等保留为历史证据和实现参考。它们可能含固定批次、固定日期或特殊修复逻辑，不属于新窗口的通用执行入口。

API 候选已存在不等于已被接受；共享配置、清单、选择表、审核索引和 output 由主窗口串行集成。数学与图像审核仍有判断工作，本包不承诺一条命令无人验收任意教材。

旧 `api_tasks.py` 仅按同名结果文件跳过；翻译候选复用也没有绑定整份上下文和提示词版本。每当题面、源图、整份英文上下文、Prompt、模型或保护规则改变，必须使用新的候选输出目录／翻译 run suffix，不能依赖旧缓存自动失效。模型、证明及特殊图题的生产仍由当前 AI 按原件裁决。

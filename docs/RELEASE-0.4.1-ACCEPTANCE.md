# 0.4.1 入口与静默运行修复验收

更新：2026-10-10。**0.4.1 已在原 TUF 更新源和公共下载页上线，真实本机后台及安装启动器已更新；网页点击、快捷方式、静默运行与资料保留验收通过。**以下区分真实使用、隔离测试和剩余边界。

## 修复范围

- 公共页主按钮改为 `http://127.0.0.1:18765/`，明确要求后台已运行。退出组件或关机后从桌面／开始菜单启动。旧 `sustech-campus://open` 浏览器点击失败由用户手动确认；桌面快捷方式和 Windows 直接协议调用成功，浏览器失败的具体根因尚未证明。
- 本机访问页通过同源认证请求复用已有 Strict Cookie，解决跨站首次导航未携带 Cookie 的情况。没有已有授权时仍停留在访问凭证页；保留 HttpOnly、SameSite=Strict、Host／Origin／CSRF 保护，没有公开校园数据或本机令牌。
- `whoami`、`icacls` 和凭据兼容 PowerShell 子进程使用 `CREATE_NO_WINDOW`；主包继续使用 GUI 子系统，后台子进程继续静默启动。
- 0.4.0 安装目录中的旧启动器须由 0.4.1 安装器更新。仅通过面板升级后台，旧安装入口仍可能闪窗。新朋友直接安装 0.4.1；其后继续使用原签名更新通道。

## 清空旧应用后的真实流程

- 在原 Windows 用户下正常卸载旧安装，移走旧数据／连接／令牌／缓存／基线／回执，以及仅有的一个、经账本和哈希确认的应用下载附件；其他下载不动。
- 旧数据完整保存在 `D:\Quarantine\SUSTechCampusDashboard\clean-install-20261010`，不自动删除、不恢复旧连接。迁移前恢复材料另行保留。
- 从公共网址完整下载 0.4.0 安装器，核对发布 SHA-256，实际交互安装。安装结束自动启动并打开 `/setup`，未使用 `/NOLAUNCH=1`。
- 用户在自动打开的 Chrome 中亲自完成首次 CAS 登录。新 DPAPI 凭据和新浏览器令牌均在清空后创建，旧运营者连接没有恢复。
- 真实同步取得 5 门课、11 项作业、56 个附件，错误来源为空。正常队列下载一个 213,581 字节附件，文件大小和 SHA-256 与回执一致；当前签名更新检查通过。
- 安装器默认未勾选桌面图标。按用户要求，将安装器生成的开始菜单快捷方式原样复制至桌面并成功启动；Windows 直接协议调用也成功。随后用户手动点击公共页旧协议链接仍失败，故不能声称旧网页入口已验收。

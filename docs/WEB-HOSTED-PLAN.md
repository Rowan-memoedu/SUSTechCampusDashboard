# 第二阶段：本机个人页、静态发布页与托管退役

更新：2026-10-08。状态：**0.4.0 已发布，真实本机迁移、静态页切换与运营者托管退役已完成**。具体证据及全新 Windows 用户首次交互使用的待验项见[阶段验收记录](LOCAL-MODE-ACCEPTANCE.md)。下文保留已确认的产品范围、执行方法和实施前基线，不表示旧托管仍在线。

本文是第二阶段唯一的范围与验收依据，保留原文件名便于已有链接继续使用。[执行交接](LOCAL-MODE-HANDOFF.md)提供新 Thread 的读序与代码入口；[第一阶段记录](HOSTED-PHASE1.md)保存历史证据；[复用与下载规则](SHARED-METADATA-AND-DOWNLOADS.md)说明新边界。

## 1. 已确认的产品决定

- 撤销运营者提供的校园业务托管，公共网站改为发布页；不再保留网站账号、邀请开通、云端 CAS 绑定、私人空间、校园业务 API、共享课程元数据服务及云端下载/打印队列。
- 全部校园业务界面由用户本机组件提供，用户在浏览器中操作。组件在后台运行，不要求用户操作独立的图形化客户端窗口，也不要求安装 Python 或使用命令行。
- 公网保留产品介绍、安装下载、打开已安装面板、更新说明、帮助、源码链接及静态签名更新源。个人页面与脚本随组件发布，不从公网动态加载能读取校园数据的业务脚本。
- 保留用户自己的 Linux 常开服务器作为个人运行端；它与运营者托管是不同概念。远程访问、认证和可选的自有执行电脑仍归该用户管理，不依赖本项目公共账号服务。
- 复用现有 Flask 页面、学校适配器、认证、下载及 SQLite 操作账本，保持现有校园功能。退出托管不等于重写应用，也不恢复已经撤销的讨论间后台监控。
- 本机首页能看到更新提醒，设置页仍能检查与安装。默认自动检查，用户点击后自动下载、校验、安装、重启并恢复页面；不默认静默安装。
- 首次安装采用“发布页下载 → 用户打开安装程序并完成系统必要确认 → 自动安装、启动组件、打开本机个人页”。已安装时，发布页可通过受约束的系统协议入口唤起组件并打开页面。
- 当前用户已批准以上开发、公开页替换和项目托管资源清理，并已按本计划执行；无需重新讨论是否保留托管。超出本计划的他人数据处置、共享资源删除或新增付费服务仍须另行确认。

旧计划中的“两种模式长期共存”“本机个人页是否接受仍待定”“公网继续展示全部私人数据”均已被本次决定取代。没有必须先由用户补答的产品选择。

## 2. 用户实际使用路径

### 首次安装

1. 打开现有公共地址的发布页，选择 Windows 安装包；Linux 提供个人运行端分发包和部署说明。
2. 下载后打开安装程序。采用当前用户安装，自动完成程序文件、快捷入口和本机打开协议的登记；无需用户配置端口、环境变量或后台服务。
3. 安装完成后启动组件，等待本机服务就绪，再打开默认浏览器中的个人页。首次使用只在本机页输入自己的 CAS，保留凭据为明确选项。
4. 提供下载目录和可选登录后后台启动设置；后台启动默认不弹浏览器。安装结束、用户点击快捷方式或“打开面板”才打开页面。
5. 首次同步有真实进度与失败提示，完成后进入已有概览。空客户端不得再跳到公共网站要求面板账号或邀请。

普通网页不能在未安装任何组件时绕过浏览器/系统许可执行安装。文案应写“下载安装”与“安装后自动打开”，不能宣传点击网页一次即全程无确认。不要要求用户关闭 SmartScreen 或安全检查。Microsoft 当前默认禁用消费者浏览器的 ms-appinstaller 协议，因此不把该协议作为普遍可用的安装入口。[R1]

工程采用现有 PyInstaller 包外的 Inno Setup 当前用户安装器，复用完整运行包，安装完成后以原用户启动；不新增 Electron/Tauri 外壳、Store 依赖或另一套更新系统。[R2][R3] 0.4.0 安装器已发布，文件名见发布页。Windows 代码签名与 TUF 包签名是不同机制，不宣称 TUF 会消除系统信誉提示。

### 日常打开、退出和设备离线

- 本机快捷方式、已打开的本机页和公共发布页的“打开校园面板”均可作为入口。
- 新增仅执行本机打开的协议操作，建议为 `sustech-campus://open`；组件未运行时先启动，已运行时复用实例。公网不需要读取本机状态或个人 JSON 来判断是否可用。
- 协议不得接受任意 URL、文件路径、命令或校园密码。本机访问凭证由启动器生成/读取并交给本机页，公共网站不得获得它。
- 浏览器拒绝唤起或未安装时，页面保留下载与打开说明；不得伪报已安装成功。手机访问发布页只提供适用平台信息，不尝试打开另一台电脑。
- 关闭浏览器后，已运行组件可以继续同步；退出组件、关机或离线时无法持续查询学校，恢复后按原规则继续。关机期间不再有运营者云端代为发现资料或保存新任务。
- 自有常开服务器可以继续执行该用户的任务。每项任务只归一个运行端负责，不默认同步凭据或同时运行两份校园写入。

### 更新与卸载

- 启动后及持续运行期间定期查询现有 TUF 源；本机首页显示可用版本、说明和安装入口，设置页保留检查、错误原因与重试。
- 点击更新后由后台组件完成下载和验证。页面显示下载、等待当前操作、重启、重新连接和最终版本；不能仅把进程退出显示为更新成功。
- 暂缓升级和更新源不可达不影响已有程序使用。签名、哈希、过期或版本校验失败时拒绝安装并保留旧程序。
- 等待进行中的学校写入、下载和回执结束后切换版本，不强杀未知结果的操作，不重放账本。新进程启动健康检查失败时恢复旧程序；不把它说成所有业务问题或数据库变更都能自动回滚。
- 更新保留 CAS 存储、偏好、资料、个人基线和操作账本。未选择保存的 CAS 在重启后可能需要重新登录，页面应解释。
- 程序文件与个人数据分开。卸载默认保留个人数据和已下载文件；仅删除本安装拥有的程序、快捷方式、自启动与协议登记。不得删除后来被另一安装接管的登记。

## 3. 运行与数据边界

公共服务器只提供静态发布材料和更新文件；个人运行端直接与学校交互。学校打印仍受校园网或 VPN 可达性约束。

- 本机监听回环地址，验证 Host、Origin、会话和 CSRF，保留 fragment 兑换本机会话的机制；回环地址不能替代认证。
- 每个用户独立进程和私密目录。禁止逐请求切换上游全局账号、借用开发者凭据或把随机实例 ID 当作访问许可。
- CAS、学校 Cookie、课表、作业、成绩、预约、下载及打印记录不发送给运营者站点。公共站点会收到正常的页面/更新请求及 IP，但不得附带课程、账号或设备执行状态。
- 本机业务资源随安装包/更新包发布；不引入第三方遥测、远程执行配置或可读取个人页数据的公共业务脚本。
- 现有本地缓存、标准化结果、同设备相同版本文件核验与复用继续保留。学生个人成绩、提交和权限本来就不能跨学生共用。
- 运营者共享元数据服务随托管一起退役，第二阶段不再提供跨用户在线课程缓存。不同用户分别读取本人获准内容，这是取消集中处理后的明确取舍；不另建隐蔽的共享 API 来维持旧指标。
- 自动保存新资料保持现有默认关闭；保留每位用户真实基线，不能把历史“58 项”或任何固定数量写成全体用户的初始基线。文件存在性、来源版本与 SHA-256 仍分别核验。
- 用户自有服务器的资料落点、执行电脑及认证必须明确；其可选配对能力不依赖已退役的运营者入口，也不能重新开放运营者托管。

## 5. 实施顺序

### A. 恢复现状与形成清单

- 读取执行交接和开发边界，核对并行改动；继续当前独立仓库，不复制整个项目或新建第二套控制面。
- 盘点本机实际安装、数据根、协议、自启动和配对；服务器盘点服务、端口、进程、活动空间、systemd 凭据、资源所有权、nginx 路由、更新源及续签任务。
- 将精确资源清单、迁移对象、保护对象和恢复办法存入私密交付目录；公开文档只存脱敏结果。资源已迁移/已不存在时按当前状态调整，不重建旧托管。
- 功能页面修改前读取 Hallmark skill：发布页按新页面流程，本机更新提醒按现有组件范围；保持现有校园业务布局，不扩张成全站重设计。

### B. 完成本机产品链路

- 将所有默认启动入口改为本机；识别旧运营者配对并停用其自动连接，保留现有本机 CAS、下载和历史。自有个人服务器配置单独识别，不能一并清空。
- 实现受限的本机打开协议、安装器、快捷方式、可选自启动、安装后等待就绪及首次本机登录。现有数据用户安装/升级不重新初始化基线。
- 复用 runtime/updates 的状态和 API 补首页提醒与重连，不在页面单独实现下载/验签。旧启动器、已登记协议和新安装路径都必须能打开实际运行的新版本。
- 保持现有业务与校历/学期筛选、资料命名、打开已保存文件、打印、写入回读等行为。

### C. 发布与迁移

- 完成双平台测试、真实分发包和全新安装验收，按 [UPDATING.md](../UPDATING.md) 生成严格递增的新版本和签名更新。
- 保留原 TUF 地址和信任链。先发布包和有版本号元数据，最后切换 timestamp；旧 0.3.5 客户端仍能通过原入口升级。
- 从旧托管迁往本机前，冻结旧端新增任务并暂停旧保留 timer，等待正在进行的写入收敛；未知结果保留待核对。迁移验收期间只有一个端负责执行任务，恢复材料不能被旧定时清理提前删除。
- 一致性导出偏好、基线、快照、必要下载状态及账本；在授权上下文中展开共享引用。导出包含版本、归属校验材料、结构和哈希清单，但导入包自报的身份不能替代登录验证。
- 按已核验账号和稳定资源/操作 ID 对齐托管数据与现有本机状态，保留本机文件、下载回执和历史；冲突保留待核对明细，不用旧托管目录整包覆盖正在使用的本机目录，也不因合并恢复已完成任务。
- 通用迁移包不携带 CAS 密码、Cookie、面板会话、设备密钥、systemd/DPAPI 密文或不可移植的绝对路径。现有同机 DPAPI 原地保留，新设备由本人重新登录。
- 区分“已见附件”和“实际已保存文件”；保留当前设备的真实文件与回执，新设备对不存在文件重新从学校取得。历史已完成/待核对写入只作历史，不进入执行队列。
- 在隔离目录验证导入、兼容性、文件核验和恢复，再切换真实数据。失败恢复旧端前先停用新端相应任务。
- 安装/迁移不能要求用户重填可恢复的普通配置。真实凭据输入、他人设备上的首次使用和系统确认由相应用户完成，不能以 fixture 冒称真实首次试用通过。

### D. 替换公共页并退役托管

- 部署静态发布页，沿用 `/app/`，实现版本、平台下载、更新说明、帮助、源码和打开已安装面板入口。静态目录可采用 `/var/www/sustech-campus-site`，与私密数据隔离。
- 移除登录、邀请、绑定、私人仪表盘及业务 API。旧私密/API 路由明确返回 410；需要保留的 GET 导航可转到发布说明，旧 POST/写接口不能重定向成其他操作。
- 验证发布页、安装下载、原 TUF 升级、用户迁移及其他站点均正常后，按下一节删除已批准的托管资源。静态网站无需 Flask、入口服务或共享元数据后台。
- 不直接运行 `deploy/retire_trial.py`：它用于重置试用，会重建目录并启动空托管服务。`reset_connections.py` 也不是迁移或最终退役工具。
- 清理源码中的默认托管路径、无用入口资源和部署说明，避免下一次安装/部署复活服务；迁移/退役仍需的代码可保留为受限维护用途。逐项说明保留原因，不为删旧测试而放松剩余业务保障。

## 6. 服务器资源处置

仅处理经实际路径解析、所有权和服务引用核实属于本项目的对象。此节给出候选清单，不是可直接复制运行的递归删除命令。

### 必须保留

- 静态更新源 `/var/www/sustech-campus-updates`、`/campus-updates/` 路由、所需 root 历史、签名元数据和客户端目标文件。不得把仍被元数据引用或恢复所需的包当作垃圾删除。
- 新静态发布页及 `/app/` 入口，服务器共享 nginx、TLS 证书和续期、宿主 systemd 凭据密钥、网络规则、SSH 以及 GraspMemoEdu 等其他项目。
- 发布者本机 `D:\AppData\SUSTechCampusPublisher` 的根／安装包签名密钥、公开镜像与发布能力；撤销业务托管不撤销更新通道。按最新确认，由服务器仅用快照／时间戳密钥每 20 天续签，每小时检查／失败重试并发邮件告警；旧 Windows 续签停用，不依赖 Codex。运行边界见 [UPDATING.md](../UPDATING.md)。
- 用户现有本机凭据、数据、已下载文件和新建的受限恢复副本。

### 迁移与恢复验证后移除

- 项目服务及 timer：campus-entry、campus-metadata、全部已盘点 campus-space 实例及模板、campus-hosted-retention，以及确认无用的旧 sustech-campus-dashboard 单元。先停止/禁用并核验无残留进程，再删除精确 unit/drop-in。
- 程序和状态：`/opt/sustech-campus-hosted`、`/var/lib/campus-spaces`、`/var/lib/campus-entry`、`/var/lib/campus-metadata`、`/etc/campus-spaces`、`/etc/campus-entry`。
- 旧备份与恢复材料：`/var/backups/campus-hosted`、`/var/lib/campus-reset-recovery`、`/var/lib/campus-hosted-recovery`。
- 旧拥有者资源：`/var/lib/sustech-room-monitor`、`/opt/sustech-room-monitor`，仅在确认无人继续使用且恢复核验完成后移除；已撤销监控保持撤销。
- `/etc/credstore.encrypted` 中精确归属这些实例的密封凭据、项目独占的服务账户/组、日志 namespace 配置和日志、构建与故障验收残留。逐个核对 UID、文件所有权、ExecStart 和消费者；不能删除整个 credstore、全机 journal 或按宽泛前缀批量删用户。
- 旧 `/spaces/`、`/campus/`、内部 auth 和命名登录跳转对应的校园代理块；保留必要 410 规则。不删除共享 nginx 文件，不整站覆盖。

2026-10-07 的上述 11 个候选目录（程序、状态、旧备份和旧拥有者资源）表观大小合计约 365 MiB；更新目录约 524 MiB，必须保留。该数字不是实际可回收块数或磁盘释放承诺，最终按退役前后实测报告。

### 恢复与删除门槛

1. 记录每个对象的绝对解析路径、类型、所属服务、大小和处置动作；拒绝越界路径、意外符号链接与未分类资源。
2. 冻结后制作一致性备份，核对 SQLite 逻辑内容、文件哈希和恢复可读性；先展开共享引用，证明新端脱离旧服务仍可读取。
3. 将仍需恢复的旧数据、配置和必要凭据备份转移到 `D:\Quarantine\SUSTechCampusDashboard\hosted-retirement-<timestamp>`，限制本机访问并核验传输和恢复。凭据备份不进入通用迁移包、Git、公开产物或报告。
4. 沿用既有 7 天恢复保留期，清单记录起止时间。服务器清理授权不包含同时永久删除该 D 盘恢复副本；到期处理另行核对，不用原服务器 timer 提前清除。
5. 本机接替、公开页与更新源验收通过后，删除清单内服务器副本、单元及独占资源；操作只针对已确认路径。发现未迁移的其他用户资料或其他项目依赖时保留该对象并报告，继续处理已明确的独立对象。
6. 回读确认进程/端口/服务不再存在、旧私密路由不可用、目录已移除，静态站/更新/TLS和其他网站正常，记录实际释放空间。最终报告区分已删除、保留恢复材料、例外和未完成项。

本计划中的前置核验是执行顺序，不是新的批准口令；范围内的开发、部署、迁移准备和已确认资源清理无需再次询问是否做。电脑整体重启、正在使用的用户应用重启按现行协作规则处理。

# 打印上传回执修复

旧适配器只按 JSON 解析上传结果，并沿用默认的 `result.html` 返回地址。学校现行网页会设置完整的打印文档页地址，并从跳转地址中的 `code` 和 `message` 读取上传回执。修复版按这一协议发送表单，同时兼容明确的 JSON 回执。

## 确认与防重复

上传只发送一次，不跟随可能重发文件的跳转。返回成功回执后，还要在官方队列中核对新增任务、文件名、份数、纸张、颜色和准确的单双面方式；双面长边与短边不会互相冒充。

学校转换文档较慢时，页面只复查队列。上传前保存的队列基线和核对信息进入原有操作账本，后台重启后仍可继续只读确认，不会重新上传。其他文件的延迟确认不会覆盖当前上传的提示。同名、同设置文档仍待核对时，不允许换一份内容再次发送；一条官方队列记录也不能同时确认两次上传。

发送前连接或准备失败会明确显示文件尚未上传。发送后的网络或回执不确定仍保留待核对状态，不会把未知结果当成成功。缺少核对信息的旧记录保留原状态。

## 验证范围

协议回执、未知格式、连接异常、延迟入队、重启恢复、设置不匹配和不重复发送均使用隔离测试。浏览器样例验证待确认到已确认的提示切换、选择文件清理及窄屏显示。

用户已手动上传需要打印的文档，本次取消重传。实际学校侧仅查询队列；未上传测试文件、重传用户文档或删除任何打印任务。因此，新上传协议的验证来自官方脚本和隔离测试，不表述为已完成新的真实上传。

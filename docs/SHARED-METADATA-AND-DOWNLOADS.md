# 共享索引、去重抓取与直达下载

日期：2026-10-07。状态：第一阶段实现已完成，具体证据和边界见 [托管第一阶段交付记录](HOSTED-PHASE1.md)。本文保留共享与下载的详细要求；下文代码差距记录的是实施前基线。

上层计划：[Web 托管试用计划](WEB-HOSTED-PLAN.md)。本文件说明共享资源与下载存储的要求；交付记录说明实际覆盖范围。当前课程目录仍需逐人核验，去重公共字段存储；已核实公共天气可合并刷新。没有把同课程关系当作跨用户权限证明。

## 1. 已确认要求

- 尽可能复用不同用户访问的相同课程信息、目录索引与公共查询结果，减少重复抓取、计算和存储。这是方案一的核心验收项。
- 大量附件和文件从学校原站直接下载到用户本机；云端不保存文件本体后再分发，即使这样能跨用户去重也不采用。
- 为实现减轻服务器压力的目标，下载设计采用浏览器/本机组件直连原站，云端只提供经过权限检查的下载定位信息；不以“不落盘流式代理”替代直连。
- 不建设云端附件仓库、文件去重池、打包下载服务或附件 CDN；不为了计算文件哈希而把原文件下载到服务器。
- 云端保存必要的元数据、资源引用、权限证据和个人状态；这些数据同样有容量、版本、过期和退出清理规则。
- “不要重复下载”分别统计：云端避免重复抓取可共享信息；同一设备避免重复保存同版本文件；不同用户设备各自从学校取得自己的一份文件是必要传输。
- 本约束覆盖下载分发链路。已有作业提交、打印上传是另一条上行数据流，应分别说明和验收，不能把本计划冒充所有文件操作均已绕过云端。

## 2. 哪些内容复用

- 公共数据：天气、公开校历、公开通知、公共字典等按来源与有效期复用；无需人为按用户复制。
- 课程公共信息：学校/系统实例、学期和官方课程 ID 相同，且字段对这些用户确实一致时，复用课程名称、简介、教学资料结构等。
- 教师发布内容：经核验属于相同可见范围和版本的公告、作业说明、普通截止规则、附件目录和文件属性按对象复用；共享元数据不含附件二进制。
- 场地和教室：只有经过核验、对相关用户一致的基础资料和脱敏可用性信息才短时复用；预约写入前仍由本人实时核验。
- 衍生结果：对相同可共享输入已存在的标准化、排序等计算，以输入版本和处理版本复用；不因此新增云端下载附件、OCR或预览处理。
- 个人叠加状态：选课归属、内容可见列表、个人截止日期例外、作业提交/成绩/反馈、我的预约、下载基线和完成回执分别保存，页面组合共享对象与个人状态。
- 混合响应必须按字段白名单拆分，不把带 Cookie、nonce、个性化链接或其他学生信息的原始 HTML/JSON 整份放入共享缓存。

“同一课程”不是充分的共享授权。Blackboard 支持按成员、分组和时间开放内容；实际学校版本和接口行为还需验证。目录相同、文件名相同、某次响应相同，也不能单独证明未来权限相同。[S1]

优先核验学校是否提供轻量的个人可见对象列表或可靠的权限范围，再共享对象详情。若只能完整读取个人目录才能确定权限，这部分请求仍必须按人执行；可以去重存储相同元数据，不能伪称已消除全部抓取。

## 3. 身份与版本

- 资源键建议包含：学校/系统实例、学期、官方课程/教学班 ID、资源 ID、响应变体与可见范围。不能按课程名或文件名合并。
- 资源版本优先使用校方返回的 revision、ETag、Last-Modified 或其他可靠变更标记；统一格式后的元数据可以另算摘要用于去重存储。
- 元数据摘要不等于附件内容哈希。校方没有提供文件哈希时，云端不下载附件补算；需要完整校验时由本机执行。
- “资源公共内容”“个人获准访问哪些对象”“个人已见/已下载状态”分开记录；每次返回共享对象前校验当前用户的授权证据。
- 同一附件 ID 更新、改名、移动目录和删除均须单独处理，不能因 ID 已见就永远认为文件版本未变。
- 带个人身份的临时地址不跨用户共享，不保存到通用索引、日志或公开 URL；尽量存稳定资源 ID 和受控的原站定位方法。

## 4. 去重抓取和更新

- 云端个人实例保留独立凭据；新增单机共享元数据协调层，负责索引、刷新任务合并和版本发布。学校请求由持有相应授权的个人实例执行，不把账号集中到一个会切换身份的上游会话。
- 对同一个资源键，只允许一个有效刷新任务。跨进程通过原子租约/唯一约束协调；其他请求等待结果或在权限有效且允许陈旧的情况下读取最近成功版本。
- 不能只用当前进程里的 `threading.Lock`。刷新失败设退避；租约超时可以恢复，过期执行者的结果不能覆盖较新版本。
- 有效期内命中共享快照不重复抓取正文；到期或有变更信号时统一刷新。校方支持时采用条件请求，304 只更新有效期，不重传完整内容。[S2]
- 分页目录的一次刷新可能需要多次请求。验收按“一轮必要请求”计数，不能把一百个分页请求宣称为一次 HTTP 请求。
- 权限/身份校验、个性化状态读取与公共内容刷新分别计数。401/403 只更新相应用户的授权状态，不把它缓存成全体用户都没有资料。
- 本人主动刷新同样受资源级合并与最小间隔约束；作业提交、预约、选退课等写操作不进入共享请求合并机制。
- 对不同课程但确实来自相同公共来源的对象，可以复用已有可证实的来源映射；来源或权限未知时不凭名称推断。
- 尊重上游缓存指示和授权约束，不把认证 HTTP 响应直接交给无用户区分的通用代理缓存。[S2]

## 5. 云端存储管理

- 单机试用优先复用 SQLite 事务与现有文件锁能力；共享元数据服务独占写入入口，个人实例通过受认证的本机接口访问。SQLite 只有一个并发写事务，刷新时不能长时间持有写锁。[S3]
- 共享主表存规范化后的当前对象和必要版本；个人表只保存授权引用、偏好和个人差异，不给每人复制完整课程目录或公告正文。
- 共享服务不提供任意文件路径、原始 SQL、任意 URL 请求或免认证的按哈希查询接口；也不把其他用户是否选课、是否命中缓存暴露给前端。
- 给字段、响应体、单对象、课程数量、历史版本、队列长度、日志与全库设置上限；禁止附件字节、Base64 文件和大文件响应混入所谓元数据。
- 用引用和最近使用信息回收无使用者或过期对象；某人退课/退出只撤销他的引用，不删除仍被他人引用的有效对象。
- 共享内容变更原子发布。用户快照记录所引用的版本，避免同一页面组合出不一致的目录与说明。
- 历史版本、错误日志、废弃租约和无效引用定期清理；数据备份范围只覆盖元数据和必要个人状态，不含下载文件本体。
- 文件数据大小增长不应带来云端磁盘或文件中转流量增长。可观测项为元数据命中率、源请求次数、刷新合并数、数据库大小和必要的权限错误，不记录账号密码或校园正文。

## 6. 文件直接到本机

### 纯 Web：优先学校正式下载入口

1. 用户在面板点击下载；后台检查当前用户有权访问该资源，只返回校方定位信息。
2. 浏览器打开学校的正式附件入口或官方课程内容页，由学校向浏览器发送文件。
3. 用户浏览器没有学校会话时，在学校官方页面完成登录；云端 CAS 会话与浏览器学校会话分别存在，不导出 Cookie 来伪装单点登录。
4. 如果学校提供适用于当前用户的短期下载链接，可以按官方机制使用；目前尚未证实存在这种能力，不能假设所有附件都有免登录直链。
5. 原站不支持面板直达下载时，明确打开官方内容页或建议可选本机组件。不能静默改用云端转发、缓存或预下载。

公网面板不能为学校域名设置登录 Cookie。普通链接导航可以离开面板去学校下载，但跨域 `<a download>` 不能保证指定文件名、保存目录或自动下载行为；需真实浏览器验收。[S4][S5]

纯 Web 不承诺关闭浏览器后还能写入本机指定文件夹，也不能把点击链接标记为已完成。无本机回执时显示“已打开原站/请在浏览器查看下载”，而非“已保存”。

### 可选本机下载组件

- 适用于自动下载、批量下载、按课程归档、断点恢复和文件完整性核验；第一阶段可作为可选增强，后期整合到方案三。
- 组件在本机建立学校会话，从学校直接拉取文件；云端只交换必要索引和任务/状态信息。不得继续从云端 `/api/attachment` 获取附件字节。
- 本机保持独立凭据，不把云端保存的 CAS 密码静默复制到设备；首次使用由用户在本机完成登录或正式授权。

## 7. 本机存储管理

- 保留用户选择的下载目录和按课程/官方目录组织的习惯；本机索引记录资源 ID、版本、相对路径、大小与 SHA-256。
- 同一设备同一版本已有完整文件时复用；用户修改过的文件保留，校方新版本采用明确版本记录和安全命名，不覆盖个人修改。
- 原子写入临时文件，完成后校验并改名；检查可用空间、单文件与总任务额度、并发数、失败重试和中断恢复。
- 浏览器原生下载采用浏览器自身的保存与权限机制；后台不能声称掌握它不可见的实际本机文件状态。
- 自动清理范围限于已识别的应用临时文件和已确认的管理规则。正式下载文件和用户修改文件不能因云端缓存过期、退课或删除引用而被自动删除。
- 跨设备需要各自的完成回执；云端有索引、A 设备下载成功，都不能使 B 设备被标成已下载。

## 8. 第一阶段实现位置

- [app.py](../src/sustech_dashboard/app.py)：课程目录继续逐实例确认个人权限；公共天气通过共享刷新协调。云端 `/api/attachment` 在权限核验后提供学校下载指引或重定向，不读取附件字节。
- [shared_metadata.py](../src/sustech_dashboard/shared_metadata.py)：实现白名单对象、个人引用、过期授权、刷新租约、条件请求、失效、退避和 SQLite 容量限制。
- [provider.py](../src/sustech_dashboard/provider.py)：保留来源元数据版本，区分个人目录、状态和公共刷新计数；没有跨用户轻量权限证明时保留个人读取。
- [materials_store.py](../src/sustech_dashboard/materials_store.py)：任务和租约逐实例保存，新用户单独建立基线；纯 Web 发现文件不冒称已保存。
- [download_agent.py](../src/sustech_dashboard/download_agent.py)：`CloudFiles.download_attachment()` 已使用本机凭据直连学校，真实附件下载已验证。
- [materials_local.py](../src/sustech_dashboard/materials_local.py)：保留原子保存、大小/SHA-256 和来源版本回执；新版本另存，保留用户改动。学校无可靠标记时，元数据指纹不能识别所有静默字节替换。
- 拥有者已完成链路切换；原文件、基线和回执保留，恢复点与实际版本见交付记录。

## 9. 必须通过的验收

- 10 个有相同已验证可见范围的 fixture 并发访问同一课程：正常刷新窗口只有一轮必要公共元数据请求，后续读取命中共享索引；各自权限校验和个人状态请求另计。
- 相同版本的公共元数据持久化一份，10 个用户保存引用和差异；同名不同课、不同学期、不同分组以及个人截止例外不误合并。
- 新公告、附件替换、权限撤销、成员退课、租约崩溃和校方 304/403 均有回归；过期任务不能覆盖新快照。
- 文件下载路径中，云端读取、转发和持久化的附件字节均为 0；检查网络流向、应用响应、nginx 临时目录和磁盘，不能只检查“没有附件目录”。
- 浏览器已登录/未登录学校、原站链接失效、需要官方页面、拒绝批量下载等情况均显示真实结果，没有云端中转回退。
- 同一设备重复任务不重复保存已核验同版本文件；第二台设备独立下载；用户修改文件保留。
- 目录索引、历史版本和日志受容量/保留规则约束；用户注销不会误删他人的共享引用，权限过期不会继续泄漏元数据。
- 真实接口的共享范围与直链能力须逐类验证；已经执行的 fixture、真实下载、隔离、升级和前端指标见交付记录。未知课程可见范围不因 fixture 通过而自动获得共享授权。

## 10. 官方资料

- [S1 Blackboard：Content Release Conditions](https://help.anthology.com/blackboard/instructor/en/course-and-content-management/content-release-conditions.html)：支持成员、分组和时间范围；用于说明同课程不必然同权限，不代表南科大当前部署已逐项验证。
- [S2 RFC 9111：HTTP Caching](https://www.rfc-editor.org/rfc/rfc9111.html)：新鲜度、验证、认证响应与共享缓存约束。
- [S3 SQLite：Transactions](https://www.sqlite.org/lang_transaction.html)：多读、单写事务及原子协调的适用边界。
- [S4 MDN：Set-Cookie](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Set-Cookie)：Cookie 的域限制，公网面板不能设置学校域 Cookie。
- [S5 MDN：a 元素](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/a)：跨域链接与 download 属性的能力边界。

# 第二阶段的复用、迁移与学校直达下载

更新：2026-10-08。真实迁移已完成，共享引用已展开，本机已独立读取；第一阶段共享服务及托管资源已退役。状态与证据见[阶段验收记录](LOCAL-MODE-ACCEPTANCE.md)，范围见[总计划](WEB-HOSTED-PLAN.md)，历史实现见[交付记录](HOSTED-PHASE1.md)。

## 1. 取消托管后保留什么

- 业务代码、模板、学校适配器和通用计算继续复用，不因执行位置改变而按用户复制开发。
- 同一用户、同一运行端保留缓存、资源 ID/版本索引、下载基线和文件核验；已有完整同版本文件可继续使用，不必重新下载。
- 每位用户直接从学校取得本人获准的数据。成绩、提交、个人截止例外、选课、预约、下载回执和学校会话不跨学生复用。
- 运营者共享元数据服务随托管退役，不再集中复用不同用户的课程抓取与存储。各设备分别保存自己需要的信息，这是已确认的取舍。
- “同一课程”不等于相同可见范围，也不等于学生个人数据相同。第一阶段本来就逐人读取课程权限与可见目录，随后对一致的白名单字段去重；不能声称此前所有课程请求都只抓取一次。
- 不为维持旧的跨用户命中率新增远程共享接口、上传课程归属或暴露其他人选课情况。未来若另行提出跨设备/跨用户共享，需要单独确定权限、数据和服务范围。

本机强隐私来自执行与页面都由个人运行端提供，不是更换 URL 路径。公开页仅导航和发布，不读取个人 JSON、学校凭据或文件。

## 2. 下载和上传的落点

- 附件由本机组件使用本人的学校会话直接读取，按用户选择的目录保存。公开发布服务器不缓存、打包或转发学校附件。
- 浏览器官方入口作为可用的辅助路径；需要学校会话时在学校页面登录。点击官方链接只能记为已打开，不能冒充本机确认保存。
- 用户自己的服务器也是个人运行端；文件存该服务器还是其配对电脑由明确配置决定。运营者发布站不参与任务下发或回执。
- 作业和打印上传沿用业务确认及回读，从本人执行端提交学校；旧运营者托管上传中转将退役。不得用附件下载的零中转证据替代上传链路验收。
- 关机或退出组件期间没有运营者云端继续发现资料。组件恢复后重新读取本人权限和变化，已有基线与未完成状态继续使用。

## 3. 本机复用与文件保护

- 用学校/系统、学期、官方课程与资源 ID、响应版本定位对象，不能只按课程名、文件名或相同大小合并。
- 元数据指纹与文件 SHA-256 分开；校方无可靠版本标记时，不能声称只看索引就发现全部同名同大小内容替换。
- 同设备同版本的重复任务核对文件存在性、大小和哈希后复用。用户修改的文件保留，学校新版另存，不静默覆盖。
- 保留当前资料的规范化显示名、目录组织与打开入口；不得恢复旧版本在所有文件名追加随机哈希的行为。
- 首次成功扫描为真正的新用户建立其自己的基线。已有用户升级/迁移保留原基线，历史验收中的 58 项或 56 项均不是固定初始化常数。
- 自动保存新资料维持默认关闭；开启后按现有规则处理新可见资料。手动批量请求跳过已核验保存的文件。
- 原子写入、磁盘空间检查、失败重试、并发上限与中断恢复继续生效。正式下载和用户修改文件不因缓存过期、退课或旧服务器删除而清除。
- 设备 A 的成功回执不能使设备 B 被标为已下载；浏览器另存文件若不在组件可验证范围内，沿用浏览器下载记录。

## 4. 托管共享引用的迁移

当前 [shared_metadata.py](../src/sustech_dashboard/shared_metadata.py) 把获准共享字段替换为 `_metadata_ref`；[app.py](../src/sustech_dashboard/app.py) 在读取时展开。原始快照不是自足的个人备份。

1. 盘点每个待迁移实例、共享引用、偏好、基线、下载状态与账本，确认归属。
2. 冻结旧端新任务，等待当前写入与回执结束；结果不明的操作保留待核对。
3. 在旧共享服务仍运行、本人授权仍有效时展开引用，形成可独立读取的个人数据包；权限失效时标注缺失并由新端重新授权读取，不越权补取。
4. 包内含版本与完整性清单。新端通过自身登录校验归属、数据格式、大小和路径；包中自报账号不是授权证明，未知字段和可执行内容不能直接执行。
5. 通用导出不含 CAS、学校 Cookie、面板会话、设备密钥或机器相关密文。原本机 DPAPI 不动；新设备重新登录。
6. 按本人身份和稳定 ID 对齐既有本机状态，保留文件和历史，冲突列为待核对；不整目录覆盖。已完成/待核对学校写入仅迁移为历史。按真实本机文件核对完成回执；没有文件的设备不能标记成功。
7. 验证断开旧共享服务仍可呈现数据、继续合法同步和读取历史，再撤销旧任务与凭据。失败恢复前先停止新端对应任务。
8. 按总计划备份、转移和删除服务器共享库及私人状态；不保留“临时”远程元数据依赖作为完成状态。

## 5. 实现入口与验收

现有组件应优先复用：

- [provider.py](../src/sustech_dashboard/provider.py)：本人权限、学期、来源版本与学校读取。
- [materials_store.py](../src/sustech_dashboard/materials_store.py)：任务、租约和状态。
- [materials_local.py](../src/sustech_dashboard/materials_local.py)：原子文件保存及版本/哈希回执。
- [download_agent.py](../src/sustech_dashboard/download_agent.py)：已有学校直连能力；退役运营者配对不等于删除所有下载逻辑。
- [local_files.py](../src/sustech_dashboard/local_files.py)：仅打开受验证的下载根目录内文件，不接收任意路径或执行程序。

必须验证：同版本复用、源版本变更、用户修改、文件缺失、断网重试、首次/既有基线差异、迁移引用展开与归属拒绝、旧端任务停用及不同设备回执独立。监测网络和磁盘，证明运营者站点不接收个人业务数据及附件；单看没有附件目录不足以证明无中转。

第二阶段不再以“10 人共享服务仅刷新一轮”为验收项。第一阶段的这项 fixture 结果保留在历史记录，不能据此宣称纯本机模式仍具备跨用户集中缓存。

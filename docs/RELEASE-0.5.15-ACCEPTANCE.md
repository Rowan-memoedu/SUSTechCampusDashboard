# 0.5.15 Windows 发布验收

## 修复

- 作业执行器现在明确当前阶段及面板负责的后续调度。旧工作流手册将独立图像复核列入整套冻结流程时，提取器只完成本阶段原页核读、候选题面和来源记录，随后由面板单独执行独立源题/解答审核。尚未轮到的审核不会再被当作资料歧义；真实缺题、版次不明、图像不可辨或独立审核失败仍会暂停。
- 提取重试先归档旧候选、旧识别结果和失败原因，再从同一份哈希核对的原件重新提取。重试不改变课程信任、首次双确认规则，也不将旧的失败结果直接改成通过。
- 通用阶段指令覆盖旧任务缓存的手册，保留原工具快照。三册核心脚本及翻译的科学正确性、内容完整性标准不变。

## 验证

- 本机作业定向回归 41 passed；本机全套 371 passed、2 skipped、2 warnings。新增回归覆盖缓存旧手册时的阶段指令、正常提取后的两种课程状态、真实来源歧义、重试归档，以及独立源题审核失败时禁止继续翻译和交付。
- 两个隔离样本实际调用 Codex Exec：完整原件成功提取并进入首次来源确认；原件缺少指定题目时返回 `needs_attention`，没有编造题面或后续通过记录。原始 PDF 哈希保持一致。
- 独立 Windows 标准用户构建、全新启动、安装注册、卸载后数据保留及真实旧版签名升级均通过。
- GitHub、静态源、TUF 和本机使用同一批文件。本机正式更新到 0.5.15，源码身份及运行文件清单核验通过，无需重新登录。
- 本机页面 375/1280 宽度、发布页 320/375/414/768/1280 宽度只读验收通过，脚本错误为 0。保留文件计数为 0，不把此项描述成非空附件集验收。
- 真实失败作业通过安装版认证重试接口成功完成提取与配图审核，证明原来的阶段误停已解除。后续独立解答审核发现两道作图题只有文字说明、缺少实际答案图，按要求拦截候选；完整生产恢复尚未在此版本验收。

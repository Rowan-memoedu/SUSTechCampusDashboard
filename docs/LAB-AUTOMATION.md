# CS109 Lab 自动化

从当前 Week 9 开始，复用校园面板的 Blackboard 认证、附件下载、作业任务账本、Codex 执行器和失败恢复。周期性读取 Labs 的 Exercise PDF；涉及 OJ 时，以对应 training 的实际题目集合为准。

Lab 分支提取 PDF 文字和原始内嵌图像，不渲染页面、不重绘图像、不生成题册 PDF；同时读取教师在同一周目录明确提供的 Java/ZIP 源码附件。源码包只读取受限的文本成员，不解压执行；原图保持原始字节、页码和哈希，生成与独立审核使用同一份冻结来源。扫描件、缺失必要图表或仍无法核实题意时保留真实缺口，不推测或自动启动页面渲染。

补齐附件后，尚未写入工程的未完成任务沿用原 job/attempt，从来源阶段重新运行；已经完成的周次不因采集能力升级被重开。Swing 教师源码可以编译，本地测试统一以 Java headless 模式运行，支持离屏绘图断言，禁止自动打开 GUI 窗口及文件、网络、反射或进程操作。

本机需已有 Academy 学习工程、JDK、IDEA Academy 与 OJ Check 桥接插件，以及 OJ 只读客户端和授权登录来源。课程、工程及工具路径保存在本机私密账本中，不进入仓库。尚未配置的实例默认关闭，面板显示配置未完成；当前个人实例从 Week 9 开始，不回填历史周次。

每次处理生成中文题面、英文文件名、练习骨架及并列参考题解。骨架保留教师提供且无需修改的基础代码，在要求学生新增或修改的位置留 `//Todo`。原题规定的 API、包名、入口和输出格式保持不变。题解通过独立来源审核和本地样例检查后才写入已有学习工程。已有学习者答案不覆盖，来源更新引起的冲突保留候选并提示处理。

写入工程和 IDEA 已加载是两个独立状态。完成生成后自动打开 IDEA；通过原生课程对象、模块源码根及 OJ Check 绑定检查后才显示接入完成。关闭应用、断网、认证失效或内存不足均保留已完成阶段并显示恢复状态，不修改系统内存设置、不自动重启用户正在使用的 IDEA。

不自动提交 OJ，不向 Blackboard 写入，不把学习结果或课程资料发到 GitHub。课程凭据只用于宿主读取，AI 仅获得隔离工作区中已暂存的必要题目资料。

界面沿用现有校园面板组件和认证保护。共用后台执行资源，避免制册与 Lab 同时启动多个 Codex 任务。现有作业制册的确认和验收规则不改变。

维护时先核对现有后台及受控恢复持有的锁。其他作业正在独占恢复时，等待其释放并恢复后台，再继续安装版验收；不要反复启动另一个后台，让暂时的锁占用触发启动器回退。IDEA 首次导入课程可能尚未建立模块，保留已写入文件并沿用 connect 自动重试；课程节点、对应模块、源码根及 OJ Check 均由原生回执确认后才算接入完成。

交付必须覆盖来源去重、失败续跑、生成与独立审核、样例和编译、保护用户修改、原生接入及面板实际显示。安装和发布沿用 deploy/release.py 与正式更新器。
